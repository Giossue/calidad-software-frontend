# Rediseño de la interfaz (estilo silabos)

Objective: redo the whole interface (look, layout, navigation, feedback) copying the reference system `~/Documentos/proyecto-grado-silabos-backend/proyecto-grado-silabos-frontend` (Vue SPA: `src/styles.css`, `src/components`, `src/layouts`, `public/logo*.png`), without touching business logic. Branch: `feat/rediseno-ui`. Delivery: work-unit commits on the branch; the user decides merge/push to `main`. Runner: `npm test` (vitest), `npm run lint` (oxlint), `npm run build`.

## Specs

- **S1 — Solo interfaz.** "sería solo la interfaz, no quiero anda de logica, porque supuestamente todo está al día". API modules (`src/lib/*-api.ts`), auth, data shaping and permissions keep their behavior. Moving inline page state into hooks is allowed only when needed to rewrite a view, with identical behavior.
- **S2 — Intuitivo.** "se quejaron que es poco intuitivo". Navigation and screens follow silabos patterns: inset sidebar with icons grouped by role, header with breadcrumb that carries the page title, page description + actions on the right, create/edit in a centered modal ("ya no se usará sheets, sino modales"), row actions in a "⋯" menu, filter toolbar (search → filters → "Quitar filtros"), pagination "1–15 de 42", back navigation that works.
- **S3 — No "IA Slop".** "se ve muy IA Slop". Adopt silabos tokens: neutral grayscale + one institutional blue (`hsl(207.7 100% 30%)`), Instrument Sans (400/500/600), radius 0.5rem, semantic shadows (control/surface/menu/modal, none for menu/modal in dark), cards `rounded-xl ring-1 ring-surface-ring shadow-surface`. Remove gradients, glows, grid overlays, pulsing pills, tinted icon tiles, raw Tailwind palette colors, arbitrary `text-[Npx]` sizes and emoji. Lucide icons at size-4 only.
- **S4 — Buen feedback.** "y que no da buen feedback, mi sistema de silabos si lo hace, eso quería que copiaramos". Every mutation shows pending (spinner replaces the button icon, button disabled), success (one toast, top-center, past-participle phrase) and error (one signal: inline in the open form/sheet, toast otherwise; field errors inline under the field with `role=alert`). No success toast for plain refresh. Destructive actions confirm with a dialog whose description states the consequence and whose action label is verb + consequence. Empty states use the `Empty` pattern with a plain sentence that changes with filters. No blank screen while loading.
- **S5 — Conservar lo que ya funciona.** Spanish accessible names used by tests and by the driver.js tours (`data-tour`, `data-tour-view`, `data-slot`, `aria-label`s, button texts in `src/features/help/page-tours.ts`) stay stable, or tests/tours are updated in the same commit. Official print reports (`src/features/reports`, `.print-root`) keep their printed layout. `npm test`, `npm run lint` and `npm run build` pass after every commit.
- **S7 — Consistencia exacta con sílabos (L4).** "los colores, deben ser los mismos que en el de silabos, porque esos son los intitucionales, lo mismo con el logo, el que tengo en el de silabos toca usar, los bordes de todos los componentes, sus sombras, radio, tipo de fuente un unico, colores de fuentes, tamaños, todo eso toca hacer consistente, los íconos TODOS que no lleven texto deben tener tooltipcontent. EL sidebar debe llevar color, ya no se usará sheets, sino modales, el fondo de los modales debe ser color oscuro, ya no un gradiente, igualito que el de silabos." Tokens copied verbatim from `proyecto-grado-silabos/resources/css/app.css`; modal overlay `bg-black/80`; every icon-only control has a `TooltipContent`. Resolved by L6: the reference is `proyecto-grado-silabos-backend/proyecto-grado-silabos-frontend` (sidebar `#122c41`, Inter, logos in `public/`).
- **S8 — Pantalla por pantalla, menos carga (L9).** "pensando en buenas prácticas, mejoremos esto … yo creo que un desplegable, no usar eso que señalo con rojo, así tienes que ir pensando en pantalla por pantalla" (cycle tabs on Estudiantes → a dropdown). Modals "deberían ser más directos, utiles en cuanto a contenido. Pero siempre siguiendo la normativa que es la lógica bpasicmanete que ya tiene, pero claro, siempre con la idea de quitar la carga excesiva al usuario." Tutorías: "porque en acciones voy a tener dos botones? … mejor que se pueda dar click en la columna y ahi que me manda a la pantalla que corresponda y ahi que salga la información separada por pestañas". "en este sistema no le pongas los íconos en los titulos en cada pantalla". "noto que falta los hover para las filas de las tablas".
- **S6 — Docs.** A frontend UI conventions doc (`docs/frontend/ui-conventions.md`) describes the adopted patterns; `AGENTS.md` points to it.
